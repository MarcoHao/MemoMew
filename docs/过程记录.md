# 过程记录

## 项目背景

这是莉莉丝 AI 应用测试题的交付作品。题目要求用AI工具独立解决一个过去工作/学习中真实遇到的重复性问题。

我的真实痛点：**日常学习和工作中，大量的碎片知识和想法散落在各个地方** —— 微信收藏、备忘录、Notion、纸质笔记本、浏览器书签……当需要回顾或关联某个知识点时，往往找不到，或者找到了也无法快速理解当时的上下文。

市面上已有的知识管理工具（Notion、Obsidian、Kimi智能助手等）要么太重（需要复杂的组织和标签体系），要么太封闭（数据在云端），要么缺乏趣味性（纯工具属性）。我想要一个**像Windows便笺一样轻、但带AI能力**的工具。

## 技术选型历程

### 第一轮：Electron vs Tauri vs 纯Web

| 方案 | 评估 | 结论 |
|------|------|------|
| Tauri | 更轻量(~5MB)，但需要Rust | 学习成本高，一天不够 |
| 纯Web | 最快，但不符合"桌面应用"要求 | ❌ 排除 |
| Electron | 120MB，但生态最成熟 | ✅ 选定 |

Electron 的成熟生态（electron-builder一键打包、丰富的IPC通信文档）是决定性因素。体积问题通过配置优化可以缓解。

### 第二轮：知识图谱方案

调研了多个开源方案：

- **Microsoft GraphRAG**: 功能完整但太重，索引成本高
- **LightRAG**: 轻量高效，但仍是Python库
- **Nano-GraphRAG**: 最简单易懂的GraphRAG实现

**最终决定**: 不引入完整的Nano-GraphRAG（会增加Python依赖和打包复杂度），而是**借鉴其思想**，用Kimi API做实体关系抽取，自己存储到SQLite，D3.js做可视化。这样完全在Node.js/JavaScript生态内，一天可以完成。

### 第三轮：语音方案

- **Kimi TTS**: Kimi目前不公开TTS API（Kimi-Audio有但不开放）
- **edge-tts**: 免费但需要Python依赖
- **Web Speech API**: 浏览器内置，完全免费，支持中文

选择Web Speech API作为最终方案。

### 第四轮：宠物形象

最初想从GameArt2D下载免费精灵图，但发现下载流程需要手动操作。考虑到一天时间限制，改为**用Canvas 2D API自己画**一个可爱的小橘猫。

虽然不如专业美术资源精美，但：
- 完全可控（可以精确控制5种状态动画）
- 零依赖（不需要加载外部图片资源）
- 包体更小

## 学到的知识

### 1. Electron IPC 安全通信

以前对Electron的`contextIsolation`理解不深。这次实践了完整的IPC通信流程：

```
主进程暴露API → preload桥接 → 渲染进程调用
```

关键点是 `contextBridge.exposeInMainWorld` 只能暴露可序列化的数据，不能传递函数引用。

### 2. Canvas 2D 动画系统

从零实现了一个简单的骨骼动画系统：
- 使用 `requestAnimationFrame` 驱动60fps
- `save()`/`restore()` 管理变换层级
- 正弦波驱动周期性动画（摇晃、摇摆）
- 状态机切换不同动画参数

### 3. D3.js Force Simulation

第一次在实际项目中使用D3的力导向图：
- `forceManyBody` 控制节点排斥力
- `forceLink` 控制边的牵引力
- `forceCollide` 防止节点重叠
- `d3.drag` 实现交互式拖拽

### 4. Tailwind CSS v4 的变化

v4引入了 `@theme` 指令来定义自定义颜色和变量，与v3的 `tailwind.config.js` 方式不同。需要直接在CSS中使用 `@theme` 块。

## 遇到的挑战

### 挑战1：better-sqlite3在开发环境加载

better-sqlite3是原生Node.js模块，在纯Vite开发服务器中无法直接加载（因为不在Electron主进程中）。

**解决**: 开发环境使用内存对象模拟数据库，生产环境通过IPC调用主进程的SQLite。在 `db/index.ts` 中做了双模式适配。

### 挑战2：TypeScript类型声明

Electron的 `window.electronAPI` 和 Web Speech API 的类型在标准TypeScript库中不存在。

**解决**: 创建 `.d.ts` 声明文件扩展全局类型：
- `src/types/electron.d.ts` — Electron API
- `src/types/speech.d.ts` — SpeechRecognition/SpeechSynthesis

### 挑战3：LightningCSS对@theme的支持

Tailwind v4使用 `@theme` 指令，但LightningCSS（Vite内置的CSS处理器）不完全支持。

**解决**: 构建仍然成功，警告不影响功能。后续可以切换到PostCSS处理Tailwind。

## 总结

这个项目验证了**AI辅助一天开发桌面应用**的可行性。核心经验：

1. **保守选型** — 用熟悉的工具链，不要在学习新框架上浪费时间
2. **MVP思维** — 砍掉所有非核心功能，先让主线流程跑通
3. **AI加速** — Kimi API承担了大部分"智能"工作（摘要、标签、实体抽取），自己只负责数据流和UI
4. **文档并行** — 开发过程中同步写文档，避免最后补文档

最终交付了一个**可用、可爱、有AI能力**的个人知识库应用，符合"便笺级轻量、AI级智能"的定位。
